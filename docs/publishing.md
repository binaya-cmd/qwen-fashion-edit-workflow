# Publishing updates

The repository includes an experimental public fashion-edit graph. Keep that status until a reproducible generation test succeeds. Use normal commits or pull requests for updates.

Before publishing, review all changed files and Git history. Exclude client/model photographs, weights, credentials, private paths, confidential prompts and paid workflow details. Inspect JSON widgets and metadata, not just filenames. Public examples need explicit clearance and an asset manifest. The included banner, concept image and test inputs are original synthetic assets; the test output is from the documented local Qwen run.

The public graph is `workflows/low-budget/Qwen_Fashion_Edit_3060.json`. Its input names are placeholders. New workflow exports must be reviewed separately; ignore rules do not protect already-tracked or force-added files.

Use general fashion and e-commerce terminology in documentation, filenames, node titles and prompts. Record validation limits honestly. Check README links, dependency filenames and final repository visibility after committing.

If a secret reaches a remote, revoke it immediately. Deleting it in a later commit does not erase history.
